# AquaTox AI — Fish Toxicity Prediction Platform

An aquarium-themed web app that predicts whether a chemical is likely to
bioaccumulate in fish tissue, using a **real model trained on your QSAR fish
bioconcentration dataset** — not a mock, not a random number generator.
`model/train.py` trains Logistic Regression, Random Forest, and XGBoost with
the exact same tuned pipeline, then **automatically deploys whichever one
scores highest F1** on the held-out test set. In this repo's own training
run that's **XGBoost** (F1 = 0.827, narrowly ahead of Random Forest's 0.825
and Logistic Regression's 0.812) — but the system doesn't hardcode that; if
you retrain and a different model wins, it gets deployed instead, and every
part of the app (API, PDF reports, dashboard) picks up the new name and its
own feature-importance ranking automatically. Check the **Model info** tab
or `model/model_metadata.json` to see which one is currently live.

```
Real dataset (779 chemicals, 9 molecular descriptors)
        │
        ▼
model/train.py  →  StandardScaler → SMOTE → GridSearchCV × 3 candidates
                    (Logistic Regression, Random Forest, XGBoost)
        │
        ▼
model/saved_model_deployed.pkl  (whichever candidate scored highest F1)
        │
        ▼
backend/  FastAPI  →  loads the pickle, serves /api/predict, /api/history,
                       /api/stats, /api/report/{id} (PDF), SQLite storage
        │
        ▼
frontend/  React + Vite  →  aquarium UI, calls the API, renders results,
                             dashboard, downloadable reports
```

## What's real here (and what's illustrative)

- **The model is real, and the choice of which model isn't hardcoded.**
  `model/train.py` reproduces your notebook's exact pipeline
  (`StandardScaler → SMOTE → GridSearchCV`, 5-fold stratified CV, scored on
  F1, 80/20 stratified split) on `dataset/Fish_concentration.csv` for all
  three models compared in the notebook (LR / RF / XGBoost), then saves
  whichever one scored highest F1 as `saved_model_deployed.pkl`. The backend
  loads that file and calls its real `predict_proba()` on every request —
  it doesn't know or care which algorithm is inside.
- **Explanations are real.** Each prediction's "what drove this result" comes
  from a SHAP explainer run against that same fitted model (a fast exact
  `TreeExplainer` for Random Forest/XGBoost, or a `LinearExplainer` if a
  future retrain ever deploys Logistic Regression instead).
- **The 8 quick-pick compounds and the "search another compound" feature are
  real rows from your training CSV** (DDT, Benzene, Bisphenol A, Naphthalene,
  Atrazine, 4-Nitrophenol, Glyphosate, Lindane, plus all 779 rows searchable
  by CAS number). Where a compound's true dataset label is known, the UI
  shows it next to the model's prediction so you can see where the model
  agrees or disagrees — the model is ~80–83% accurate, not perfect, and the
  app is honest about that.
- **The organ/skeleton visualization is illustrative**, not a second trained
  model. The binary safe/dangerous prediction is real; which organs light up
  (gills, liver, kidneys, heart) follows a simple, clearly-labeled rule based
  on the input profile, for educational value.

## Setup

### 1. Train the model (one-time)

```bash
python3 -m venv .venv && source .venv/bin/activate      # optional but recommended
pip install -r requirements.txt

python model/train.py
```

This runs the full `GridSearchCV` for Logistic Regression, Random Forest, and
XGBoost (a minute or two), then writes `saved_model_deployed.pkl` (whichever
model won), plus `saved_model_lr.pkl` / `saved_model_rf.pkl` / `saved_model_xgb.pkl`
for comparison, `scaler.pkl`, and `model_metadata.json` into `model/`.
`xgboost` is optional — if it isn't installed, training still completes with
LR + RF and deploys whichever of those two scores higher F1.

### 2. Run the backend

```bash
uvicorn backend.app:app --reload --port 8000
```

API docs (Swagger UI): http://localhost:8000/docs
A SQLite database is created automatically at `backend/database/history.db`.

### 3. Run the frontend

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173 — the Vite dev server proxies `/api/*` to the
backend on port 8000 (see `frontend/vite.config.js`).

For a production build:

```bash
npm run build      # outputs frontend/dist
npm run preview    # serve the production build locally
```

## Design notes / honest trade-offs

- **The deployed model is chosen automatically, not hardcoded**, because a
  real Python backend can load whatever pickled model wins directly — no
  need to hand-port tree logic into JavaScript the way a browser-only demo
  would. All three candidates' test-set metrics live in
  `model_metadata.json` and are shown side-by-side in the **Model info**
  tab, with the winner clearly tagged `deployed`.
- **Tailwind is wired up** (see `tailwind.config.js`) but most of the
  aquarium visual system — the tank, bubbles, fish animation, skeleton
  reveal — is hand-written CSS in `src/index.css`, since fine-grained
  keyframe animation isn't a good fit for utility classes.
- **Recharts** is used in place of Chart.js — it's the React-idiomatic
  equivalent and avoids manual canvas lifecycle management inside React.
- **Three.js was intentionally left out.** A hand-tuned SVG/CSS fish gives
  more reliable, controllable results (exact skeleton-only-on-death
  behavior, predictable performance) than a WebGL scene for this scope.
